# ARMANI — оновлення профілю та адміністратора

Це повний пакет для https://armani-famili.vercel.app/ з плоскою структурою файлів. Він ще не встановлений у вашому Supabase і не опублікований у Vercel.

Власник: Discord **768426180709711882**.
Бот, який ви вказали: **1555591785630146721**. ID бота не є ключем доступу та не дає доступу до його коду чи статистики.

## 1. Установіть базу

У Supabase вашого проєкту відкрийте SQL Editor → New query.
1. Скопіюйте весь вміст `setup/01-schema.sql`, натисніть Run.
2. У новому запиті виконайте `setup/02-admin.sql`. Ваш ID уже підставлено.

Перший файл створює таблиці, політики доступу та публічне сховище зображень. Повторний запуск не замінює вже збережені записи. Другий надає права вашій перевіреній Discord-ідентичності. Не додавайте туди ID бота.

## 2. Оновіть сайт

Збережіть поточну версію репозиторію. Розпакуйте архів і завантажте ВМІСТ у корінь `shavera149/Armani-vercel`, замінивши однойменні файли. `index.html`, `auth.js`, `dashboard.js`, `vercel.json` і CSS мають бути в корені; `api/ranking-sync.js` має залишатися всередині папки `api`. Не створюйте додаткову батьківську папку.

Завантажте також `.vercelignore`: він виключає інструкції, SQL, тести та адаптер бота з публікації. Секретів у пакеті немає. Не завантажуйте власний `.env` у GitHub.

Vercel: Framework Preset — Other, Root Directory — корінь репозиторію. Використовуйте наданий vercel.json; після коміту дочекайтеся нового Production deployment. Не повертайте старий deployment через Promote.

## 3. Перевірте вхід і права

На сайті вийдіть та увійдіть через Discord обліковим записом 768426180709711882.
- Заповніть нікнейм і Static ID → Зберегти. Вони зберігаються в профілі Supabase Auth, а не лише в браузері. Після повторного входу або входу з іншого пристрою мають залишитися. Static ID зберігається рядком, з початковими нулями.
- Через «Мій профіль» можна змінити ці поля. Це самостійно вказані дані персонажа, їхню відповідність NG сайт не перевіряє.
- Власник бачить позначку адміністратора й кнопки редагування трьох карток вищого складу, статистики, трьох машин, трьох комплектів одягу та маєтку.
- Фото: JPG, PNG або WebP до 5 МБ. Збережені фото й контент видно всім; оновлення перевіряються кожні 30 секунд.
- У приватному вікні без входу кнопок редагування бути не повинно. Інший Discord-користувач також не отримує прав. Перевірка виконується політиками бази, а не лише приховуванням кнопок.

Якщо кнопок немає: перевірте успішне виконання обох SQL-файлів, акаунт Discord, вийдіть та увійдіть знову. Не надавайте права через user_metadata — вони призначені лише для профілю.

Старі замінені фото залишаються в Storage, щоб паралельне редагування не видалило потрібне зображення. Невикористані файли можна пізніше прибрати вручну, перевіривши image_path у armani_media.

## 4. Підключіть рейтинг бота

Профіль, фото й адмін-редактор працюють без цього кроку. До першої синхронізації таблиця повідомляє, що бот ще не передав рейтинг. Початкові інші значення позначені демонстраційними.

Потрібні **ID Discord-сервера** і доступ до коду/хостингу вашого бота. Наданий ID 1555591785630146721 — це ID бота, а не сервера. Щоб знайти ID сервера: увімкніть Developer Mode у Discord → правою кнопкою на сервері → Copy Server ID.

У Vercel → Project → Settings → Environment Variables додайте для Production:

| Змінна | Значення |
| --- | --- |
| SUPABASE_SECRET_KEY | Секретний ключ sb_secret_… вашого Supabase, не publishable key |
| BOT_SYNC_TOKEN | Новий випадковий секрет, щонайменше 32 символи |
| DISCORD_GUILD_ID | ID вашого Discord-сервера |

Новий секрет можна створити локально командою `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.

Після змін змінних зробіть Redeploy. Секретний ключ Supabase залишається тільки у Vercel. Токен Discord залишається тільки на хостингу бота. Не надсилайте жоден із них у чат чи репозиторій.

На хостингу наявного Node.js-бота (Node 20+) задайте **той самий BOT_SYNC_TOKEN** і **DISCORD_GUILD_ID**. Додайте до коду файл `bot/ranking-sync.cjs`.

Викликайте адаптер після того, як бот сам підрахував достовірні XP:

```js
const { syncArmaniRanking } = require('./ranking-sync.cjs');

// Значення нижче повинні надходити з реальної бази вашого бота.
const snapshot = {
  version: Date.now(),
  entries: participants.map(p => ({
    discord_id: String(p.discordId),
    nickname: p.characterName,
    xp: p.xp
  })),
  family_rank: family.rank,
  points: family.points,
  members: family.memberCount
};
await syncArmaniRanking(snapshot);
```

Це приклад інтеграції, а не самостійний бот: `participants` і `family` треба взяти з його наявного джерела даних. Не приймайте XP від довільних користувачів через незахищену команду.

Передавайте повний знімок до 100 учасників (або сформований ботом топ-100), а не лише одного зміненого учасника: новий знімок замінює попередній. Сайт показує топ-3. Якщо запит не вдався, повторюйте той самий знімок із тією самою version; старі/повторні версії ігноруються. Показники сім’ї та учасників оновлюються атомарно; кількість авто залишається під ручним керуванням адміністратора.

Наступний знімок бота може замінити ручні зміни рейтингу сім’ї. API NG не надано, тому автоматичного отримання статистики з GTA немає: джерелом буде ваш бот. Адаптер не запускає бота і не реєструє Discord-команди. Для остаточного підключення потрібен код бота без секретів або опис його бази рейтингу.

## Перевірено та що залишилося перевірити

Локально перевірено синтаксис JavaScript і обробник API з імітованим Supabase: авторизацію ключем, ID сервера, неправильні/дубльовані записи, діапазони XP, розмір запиту, збої сховища та відсутні налаштування. Тест: `node tests/ranking-api.cjs`.

SQL не виконувався у вашій базі, а реальний OAuth, завантаження Storage та синхронізація бота потребують перевірки після встановлення. Обов’язково перевірте запис як власник та відмову для іншого акаунта. Попередні налаштовані широкі політики Storage можуть додавати доступ: політики інших застосунків цей пакет не видаляє.
